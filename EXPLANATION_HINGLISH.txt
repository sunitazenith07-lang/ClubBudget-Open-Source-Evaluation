--------------------------------------------------------------------------------
Ye project "RewardBook" ek Fintech Loyalty Rewards System hai.
Isme basic requirements ye thi:

- Promotional bonus percent aur points cap apply karna.
- Agar koi transaction refund ho, to proportionally points reverse karna (kabhi bhi awarded se zyada reverse na ho aur balance negative na ho).

- Same account, date aur amount par repeat hone wale transactions ko flag karna (operations review ke liye).

3. KYA KYA BUGS THE AUR UNHE KAISE DEBUG & FIX KIYA?
--------------------------------------------------------------------------------

BUG #1: Points Calculation me Rounding aur Cap Zero ka Issue (service.py me calculate_points)
-----------------------------------------------------------------------------------------------
* Root Cause / Problem:
  1. Starter code me round() use ho raha tha:
     `base = round(amount_paise / 10000) * points_per_100_rupees`
     Isse 19,999 paise (Rs 199.99) round hokar 2 points ban raha tha, jabki rule kehta hai
     ke integer floor division hona chahiye: 19999 // 10000 = 1 point!
  2. Cap Zero bug:
     Starter code me likha tha:
     `if cap_points:`
     `    points = min(points, cap_points)`
     Python me 0 'falsy' hota hai! Jab kisi rule me cap_points = 0 pass kiya gaya, to
     Python ne `if cap_points:` ko False maan kar ignore kar diya aur poore points de diye!
     Rule kehta hai: "A cap of zero means zero points."
  3. Negative aur Boolean Types:
     Negative amount ya negative rules par 0 points aane chahiye the. Aur Python me
     `bool` class `int` ki subclass hoti hai (`isinstance(True, int)` is True), to boolean
     values integer validation ko bypass kar rahi thi.

* Humne kya Fix kiya:
  1. Rounding hata kar integer floor division lagaya:
     `base = (amount_paise // 10000) * points_per_100_rupees`
     `points = base * (100 + bonus_percent) // 100`
  2. Explicit check lagaya:
     `if cap_points is not None:`
     `    points = min(points, cap_points)`
     Aur agar cap_points <= 0 ho to 0 return kiya.
  3. Strict type validation lagayi:
     `if isinstance(amount_paise, bool) or not isinstance(amount_paise, int) or amount_paise <= 0: return 0`
     Isse boolean, negative, string, floats sab securely reject ho gaye.


BUG #2: Idempotency aur Replay Defect (service.py me apply_reward_event)
-----------------------------------------------------------------------------------------------
* Root Cause / Problem:
  Starter code me event check kiye bina seedha process kar deta tha aur function ke end me:
  `out['processed_event_ids'].append(event_id)`
  Agar same event dubara bhej diya jaye (event replay), to starter code usko firse process
  kar deta tha, points dobara jud/ghat jaate the, aur processed_event_ids me ['E1', 'E1']
  duplicate entry ban jaati thi.

* Humne kya Fix kiya:
  Function ke start me hi early return guard lagaya:
  ```python
  if not event_id or not isinstance(event_id, str):
      return out
  if event_id in out['processed_event_ids']:
      return out
  ```
  Agar event_id pehle se process ho chuka hai, to function turant return ho jata hai
  bina account ko mutate kiye ya ledger me duplicate daale. Isse purchase aur refund dono
  ki replay idempotency 100% guarantee ho gayi.


BUG #3: Refund Bounds aur Cumulative Integer Reversal Drift (service.py me refund_processed)
-----------------------------------------------------------------------------------------------
* Root Cause / Problem:
  1. Refund validation nahi thi: Agar refund amount negative ho (-1), zero ho, ya purchase
     amount se bada ho (150,000 paise on 100,000 paise purchase), to bhi starter code usko
     accept kar leta tha aur balance bigaad deta tha.
  2. Truncation Loss / Drift across Multiple Partial Refunds:
     Agar kisi transaction par 15 points award hue the (e.g. Rs 1000 with 50% bonus), aur
     customer ko do baar 50%-50% partial refund mila:
     - Incremental calculation: (15 * 50000) // 100000 = 7 points.
     - Second refund: (15 * 50000) // 100000 = 7 points.
     Total reversed = 7 + 7 = 14 points!
     Poora 100% refund hone ke baad bhi account me 1 point orphaned reh jaata tha!

* Humne kya Fix kiya:
  1. Strict input validation lagayi:
     ```python
     if isinstance(refund, bool) or not isinstance(refund, int) or refund <= 0:
         return out
     if txn['refunded_paise'] + refund > txn['amount_paise']:
         return out
     ```
  2. Cumulative Reversal tracking formula implement kiya:
     Har transaction me `refunded_paise` aur `reversed_points` track kiya.
     `new_refunded = txn['refunded_paise'] + refund`
     `should_reverse = (txn['awarded_points'] * new_refunded) // txn['amount_paise']`
     `delta = max(0, should_reverse - txn['reversed_points'])`
     Ab dekho:
     - First 50% refund: should_reverse = (15 * 50000) // 100000 = 7. Delta = 7.
     - Second 50% refund: should_reverse = (15 * 100000) // 100000 = 15. Delta = 15 - 7 = 8!
     Total points reversed = 7 + 8 = 15 points! Exact 100% points reverse hue, zero drift!
  3. Balance Non-negativity check:
     `delta = min(delta, max(0, out['points_balance']))`
     Isse balance kabhi bhi negative nahi ja sakta.
